# MeetingRecorder

Windows 11 向けの **ポータブル会議録音アプリケーション**です。
**録音を最優先**し、文字起こしは**録音のあとで**、ユーザーが指示したときだけ
**完全にローカルの Whisper** で実行します。

ZIP を展開して `MeetingRecorder.exe` を起動し、「録音開始」を押すだけで、
**マイク（同じ部屋の参加者）と PC 内部音声（Zoom / Teams / Meet / ブラウザなど、
Windows が再生している音すべて）を同時に録音**します。

手元にある音声ファイル（WAV / MP3 / M4A / AAC）を読み込んで
文字起こしすることもできます。

インストール不要・管理者権限不要・会議データの外部送信なし。

---

## この2経路だけです

```
[A] このアプリで録音する
    録音開始 → マイク + PC内部音声を録音 → 録音停止 → 録音ファイル完成
      → ユーザーが「文字起こし」を押す → ローカルWhisperで文字起こし
      → 結果を表示・編集 → 必要なら議事録生成

[B] 既にある音声ファイルを使う
    「音声ファイルをインポート」 → アプリ内に読み込む
      → ユーザーが「文字起こし」を押す → ローカルWhisperで文字起こし
      → 結果を表示・編集 → 必要なら議事録生成
```

**録音中に文字起こしは一切行いません。**
録音を停止しても、文字起こしは自動的に始まりません。

```
録音停止 ≠ 文字起こし開始
```

この2つは完全に別の操作です。理由は単純で、**文字起こしは何度でもやり直せますが、
録音できなかった音声は取り戻せない**からです。録音中は録音以外の重い処理を行いません。

## アプリ概要

| 機能 | 内容 |
| --- | --- |
| マイク録音 | WASAPI で任意の入力デバイスから取得 |
| PC内部音声録音 | **WASAPI ループバック**。再生デバイスの出力全体を取得（特定アプリ専用ではありません） |
| 録音中の処理 | 録音のみ。**モデルの読み込みも推論も話者分離も行いません** |
| 音量調整 | 録音終了後に、ファイル全体へ**一定倍率のゲインを1回だけ**適用。ゲート／AGC／コンプレッサー／リミッターは**使いません** |
| 保存 | ミックス済みの **1ファイル**（既定 MP3 192kbps・約86MB/時。WAV 無圧縮も選択可） |
| 文字起こし | whisper.cpp による日本語認識。**完全ローカル・CPU実行・手動実行** |
| 音声インポート | WAV / MP3 / M4A / AAC を読み込んで文字起こし。元ファイルは変更しません |
| 発言元 | このアプリで録音した場合、「マイク」「PC音声」を録音ストリームで確定（AI推測ではありません） |
| 話者分離 | 録音した会議のみ。文字起こし時に `Speaker 1/2/...` を付与（実験的・精度は限定的） |
| 議事録 | 文字起こし結果がある場合のみ手動実行。ローカルLLM または 抽出型（実験的） |
| クラッシュ復旧 | 停止ボタンを押さずに落ちてもデータが残り、次回起動時に復旧 |
| 性能自動調整 | PC性能を**実測**してモデル・スレッド数・機能を自動選択（設定画面で変更可能） |

## 対応OS・必要PC性能

| 項目 | 要件 |
| --- | --- |
| OS | Windows 11（Windows 10 でも動作します） / x64 |
| 管理者権限 | **不要** |
| CPU | 4コア以上を推奨。基準環境: Intel Core i5-1335U。**録音自体はほとんどCPUを使いません**（文字起こしを実行したときだけ負荷がかかります） |
| RAM | 8GB 以上（推奨 16GB） |
| GPU | **不要**。CPU のみで動作します（NVIDIA GPU は不要） |
| ディスク | アプリ約 300MB + モデル（31MB〜547MB）+ 録音データ（既定の MP3 192kbps で約86MB/時、WAV なら約346MB/時。録音中は一時的に WAV 相当が必要）+ 文字起こし用作業音声（**1系統あたり約115MB/時**、既定では2系統） |
| 事前インストール | .NET / Python / Node.js / Visual C++ ランタイム いずれも**不要** |
| 仮想オーディオドライバ | **不要**（VB-CABLE、Stereo Mix 等に依存しません） |

## プライバシーと外部通信

このアプリは会議データを機密情報として扱います。

**自分で確認する方法**

```
MeetingRecorder.exe --diagnose          # アプリ自身が保持する外向き接続を表示
tools\Verify-NoNetwork.ps1 -Minutes 10  # プロセス外部から接続を監視
```

**送信しないもの（実装上、送信経路が存在しません）**

- マイク音声 / PC内部音声 / 録音データ
- 文字起こし / 議事録 / 発言者情報
- 利用状況・クラッシュログ・アクセス解析（テレメトリーは一切ありません）

**使用していないクラウドサービス**

OpenAI API、Anthropic API、Gemini API、Azure Speech、Google Speech、
AWS Transcribe、その他クラウド AI / STT API。

**唯一の外部通信: AIモデルの初回ダウンロード**

- ユーザーが明示的にボタンを押した場合のみ実行されます。
- 開始前に、モデル名・用途・配布元・URL・ファイルサイズ・保存先・
  ライセンス・SHA-256 を画面に表示します。
- URL は `ModelCatalog` にハードコードされた許可リストのみ。
  任意の URL を入力する機能はありません。HTTPS 以外は拒否します。
- ダウンロード後に **SHA-256 を照合**し、不一致ならファイルを削除して失敗させます。

**ログ**

技術ログ（エラー、デバイスイベント、バッファ状況、文字起こしの処理時間など）は
ローカルにのみ保存されます。会議本文や文字起こし全文はログに複製しません。

**インポートした音声について**

読み込んだ元のファイルは読み取るだけで、変更・移動・削除・送信のいずれも行いません。

## 入手と起動方法

1. [Actions タブ](../../actions/workflows/build-windows.yml) を開き、
   **緑のチェック ✅ が付いた実行**をクリックします。
2. 開いたページを**いちばん下までスクロール**します。
   最下部に **Artifacts** という見出しの箱があり、その中に
   `MeetingRecorder-win-x64` があります。クリックでダウンロードされます。
3. ダウンロードした ZIP を右クリック →「プロパティ」→ 下部の
   「**ブロックの解除**」にチェック → OK。
   （インターネット由来の印を外しておくと、展開後の警告が減ります）
4. **2 回展開します。** GitHub は Artifacts を ZIP で包んで配るため、
   二重の ZIP になっています。

   ```
   MeetingRecorder-win-x64.zip      GitHub が包んだ外側
   └─ MeetingRecorder-win-x64.zip   本体
      └─ MeetingRecorder.exe ほか
   ```

5. 書き込み可能な任意のフォルダーに展開します。
   （例: `C:\Users\<ユーザー名>\Tools\MeetingRecorder\`。Program Files 配下は避けてください）
6. `MeetingRecorder.exe` をダブルクリックします。

**Artifacts が見つからないとき**

| 症状 | 原因と対処 |
| --- | --- |
| Artifacts の箱が無い | **ジョブのログ画面**を開いています。パンくずでひとつ戻り、実行サマリーのページを開いてください |
| 箱はあるが押せない | GitHub に**ログインしていない**状態です。Artifacts のダウンロードにはログインが必要です |
| 実行が黄色い ● のまま | ビルド完了前です。Artifacts は**全ステップ終了後**に現れます |

**Artifacts は 30 日で削除されます。** 恒久的な配布が必要な場合は、
タグ `v*` を push してください。GitHub Release（**下書き**として作成されます）から
ログインなしで取得できるようになります。

### 最初に 1 回だけ実行することを推奨します

展開したフォルダーでコマンドプロンプトを開き、次を実行してください。
マイク・PC内部音声・保存先・空き容量・外部通信の状態を **実測** して表示します。

```
MeetingRecorder.exe --diagnose --seconds 10
```

実行中の 10 秒間、マイクに向かって話し、PC で何か音声（動画やテスト音）を再生してください。
ここで `D-04`（マイク）と `D-05`（PC内部音声）が **[ OK ]** になれば、その PC で
本アプリの中核機能が動くことが確認できたことになります。逆にここでエラーが出た場合は、
録音を始める前に表示された対処を行ってください。

## 初回設定

初回起動時にウィザードが表示されます。

1. **マイク** — 入力デバイスを選択（既定デバイスに追従させることもできます）
2. **PC音声** — ループバック取得元の再生デバイスを選択
3. **保存先** — 録音データを保存するフォルダーを選択
4. **AIモデル** — 「PC性能を測定」→「モデルをダウンロード」

設定はローカルに保存され、2 回目以降は
**`MeetingRecorder.exe` を起動 → 「録音開始」** だけで使えます。

> モデルを取得しなくても **録音は利用できます**。その場合、文字起こしのみ行われません。

## AIモデルの取得

| モデル | サイズ | ライセンス | 用途 |
| --- | --- | --- | --- |
| Whisper tiny (q5_1) | 約31MB | MIT | 最軽量。処理時間を最優先する場合 |
| Whisper base (q5_1) | 約57MB | MIT | 軽量 |
| Whisper small (q5_1) | 約181MB | MIT | 精度と処理時間のバランス |
| Whisper medium (q5_0) | 約514MB | MIT | 高精度 |
| Whisper large-v3-turbo (q5_0) | 約547MB | MIT | **最高精度**。処理時間は長くなります |
| Qwen2.5 1.5B Instruct (GGUF) | 約1.04GB | Apache-2.0 | 議事録生成（既定） |
| Qwen2.5 3B Instruct (GGUF) | 約1.96GB | Qwen Research License | 議事録生成（**自動選択されません**。社内利用可否の確認が必要） |

**文字起こしモデルは1つだけ**です。以前あった「リアルタイム用の軽いモデル」と
「やり直し用の重いモデル」という二重構成はありません。

初期値は PC 性能の**実測結果**から自動的に決まりますが、
**設定画面でいつでも変更できます**。モデルを選ぶと、そのPCでのおおよその処理時間
（音声長の何倍か）が表示されます。これは実測スコアから換算した**推定値**であり、
そのモデルを実際に走らせて測った値ではありません。

リアルタイム性の制約がなくなったため、モデル選定の基準は
「録音に追いつけるか」ではなく
**日本語の認識精度 × 実用的な処理時間 × 16GB RAM での安定動作**です。

> **large-v3-turbo について**
> whisper.cpp（Whisper.net 1.8.1 同梱）が large-v3-turbo 形式を読めることは、
> CI 上の Windows ランナーで実モデルを読み込み・推論して確認しています
> （`.github/workflows/build-windows.yml` の `evaluate_models`）。
> ファイルサイズと SHA-256 は配布元から実際にダウンロードして測定した値です
> （`.github/workflows/model-hashes.yml`）。
>
> **turbo は medium より速くはありません。** 同じ CI ランナー（4論理コア / 2スレッド）
> で同一音声を処理したところ、推論時間は small 12.17 秒 / medium 38.67 秒 /
> turbo 66.36 秒でした（TEST_RESULTS.md 2.15）。turbo が「速い」のは large-v3 と
> 比べての話です。そのため **turbo を無条件に既定にはしていません**。自動選択は
> 実測スコアから「音声長の 1.5 倍以内で終わる見込みか」で判断するため、
> 基準環境クラスのPCでは small が選ばれ、turbo は
> 「時間をかけてでも精度を取りたいとき」に設定画面から選ぶモデルになります。
> **基準PC（Core i5-1335U）での処理時間・メモリ使用量は未実測です**
> （測定したのは CI ランナーであって基準PCではありません）。
> q8_0（約834MB）と f16（約1.51GB）のビルドも測定しましたが、16GB 環境で
> Windows・ブラウザ・会議クライアントと共存させる余裕が乏しいため同梱していません。

## 録音する

1. （任意）会議名を入力します。フォルダー名に使われます。
2. 録音開始前に、左パネルの **マイク／PC内部音声のレベルメーター**が
   振れていることを確認してください。片方が無音のまま 1 時間録音してしまう事故を防げます。
3. 「● 録音開始」を押します。

### どちらか一方だけを録音する（ミュート）

レベルメーターの下にあるチェックボックスで、系統ごとにミュートできます。

| やりたいこと | 操作 |
| --- | --- |
| **PC内部音声だけ録音**（ウェビナー・動画など） | 「マイクをミュート」をオン |
| **マイクだけ録音**（対面の会議、口述録音） | 「PC内部音声をミュート」をオン |

- **録音中でも切り替えられます。** 次のブロックから即座に反映されます。
- ミュート中の音声は、**録音ファイルにも文字起こしにも入りません**。
  レベルメーターも無音を示します。
- 設定は記憶されます。毎回ウェビナーを録る場合、マイクを毎回オフにする必要はありません。
- 両方ミュートすると無音のファイルになります。その場合は警告を表示します
  （禁止はしません。無音で録りたい状況もあり得るためです）。

録音開始時に以下が自動チェックされ、問題があれば
**原因と対処方法**が表示されます（"Error" だけの表示はしません）。

- マイクが取得できるか
- PC内部音声が取得できるか
- 保存先に書き込めるか
- 十分な空き容量があるか
- STTモデルが利用可能か

録音中に表示されるのは、**録音の状態だけ**です。

- 録音中である旨と経過時間
- マイクのレベルメーターと状態
- PC内部音声のレベルメーターと状態
- エラー・警告
- 診断情報（CPU / RAM / 書き込み量 / バッファ溢れ / 無音補間 / 同期補正）

**録音中に文字起こし欄が動くことはありません。** 文字起こしは行っていないためです。

録音中は Windows のスリープが抑制され、停止すると元に戻ります。

### 録音を停止したら

```
録音を停止しました
```

ここで**いったん終わり**です。文字起こしは自動的に始まりません。
必要になったときに「文字起こし」を押してください。翌日でも構いません。

## 音声ファイルをインポートする

コマンドバーの「**音声ファイルをインポート...**」から、手元の音声ファイルを
読み込んで文字起こしできます。

| 形式 | 対応状況 |
| --- | --- |
| `.wav` | **対応**。このアプリ自身のリーダーで読むため、OS のコーデックに依存しません |
| `.mp3` | **対応**（Windows の Media Foundation デコーダーを使用） |
| `.m4a` | **対応**（同上・AAC） |
| `.aac` | **環境依存**。下記の注記を参照してください |

- 読み込んだ**元のファイルは変更・移動・削除しません**。読み取りのみです。
- 保存先の下に会議フォルダーが1つ作られ、その中に文字起こし用の作業音声
  （16kHz / モノラル / PCM）が作られます。
- 元ファイルのパスは記録されるため、作業音声を削除したあとでも、
  元ファイルが同じ場所にあれば作り直して再文字起こしできます。

> **`.aac` についての正確な説明**
> `.m4a`（MP4 コンテナの AAC）は CI で実際に往復テストしています。
> 一方、コンテナを持たない生の ADTS ストリーム（`.aac`）を Media Foundation が
> 開けるかどうかは、そのPCに登録されたバイトストリームハンドラーに依存します。
> CI では真の ADTS ファイルを生成する手段がないため、**この形式は未検証**です。
> 開けない場合は、理由を表示して読み込みを拒否します（壊れた作業ファイルを
> 作ったり、無言で失敗したりはしません）。WAV へ変換してから読み込んでください。

> **Windows N / KN エディションについて**
> MP3 / M4A / AAC のデコードは Windows の Media Foundation を使います。
> N / KN エディションでは Media Feature Pack を入れるまでこれらは使えません。
> その場合も **WAV のインポートは動作します**。

### インポートした音声では話者を推測しません

インポートされるのは1本の音声です。そこには
「どちらがマイクでどちらがPC音声か」も「誰が話しているか」も記録されていません。
したがってこのアプリは、インポート音声に対して

- `マイク` / `PC音声` の分類
- `Speaker 1` / `Speaker 2` の付与

を**一切行いません**。すべての発言は「インポート音声」という中立的な名前になり、
「話者名を編集」も無効になります（理由を表示します）。

## 文字起こし

**ユーザーが「文字起こし」を押したときだけ**実行されます。
録音中でも、録音停止時でも、自動的に始まることはありません。

押すと、はじめてそこで Whisper モデルが読み込まれ、保存済みの音声を先頭から
解析します。進捗が表示され、いつでも中止できます。

```
文字起こし中... 34%（01:22 / 04:03）
```

処理中も**録音データそのものには一切書き込みません**。読み取るだけです。

表示例:

```
[00:01:24] マイク
今回のKPIについて確認します。

[00:01:31] PC音声 / Speaker 1
はい。前月実績についてですが……
```

- **本文はその場で編集できます**（誤変換の修正、削除、追記）。
- 「話者名を編集」で `Speaker 1 → 大西` のように変更でき、
  その会議内の同じ話者の発言すべてに一括反映されます。
- アプリが人物名を推測することはありません。実名はユーザーが入力した場合のみ表示されます。
- **何度でも実行できます。** 別のモデルに変えてやり直すこともできます。
  結果は毎回まるごと置き換わります。

### 何が起きるか

| 段階 | 内容 |
| --- | --- |
| モデル読み込み | 設定画面で選んだモデルを読み込みます（数秒〜数十秒） |
| 音声の分割 | **無音の位置**で、**最大27秒**の窓に区切ります |
| 認識 | **ビームサーチ（幅5）+ 温度フォールバック**、日本語用の短いプロンプト付き |
| 話者分離 | 録音した会議のみ。認識のあとに実行します（実験的） |
| 保存 | `transcript.txt` / `transcript.md` を書き出します |

27 秒という上限は、Whisper の受容野が 30 秒であることによります。
これを超える窓はエンジン側で黙って切り捨てられるため、
**切る位置をこちらで決め、必ず無音に置く**方針にしています。
短い数秒のチャンクを毎回文脈なしで処理する方式は使いません。
録音に追いつく必要がなくなったため、精度を優先できるようになったためです。

### 発言元は推測ではありません（アプリで録音した場合）

このアプリで録音した会議では、**混合ファイルではなく系統別の音声**を読み直します。
そのため「マイク／PC音声」の区別は推測ではなく、録音時の事実がそのまま残ります。
**手動で付けた話者名も、やり直したときに引き継がれます。**

そのために、録音中は作業用の音声を会議フォルダーに保存します。

```
recognition-mic.wav      マイク系統（16kHz / モノラル / PCM）
recognition-system.wav   PC音声系統（同上）
```

1系統あたり**毎時およそ115MB**です。混ぜてしまうと発言元の区別は二度と復元
できないため、録音中に分けて保存する以外の方法はありません。
設定の「**文字起こし用の音声を保存する**」をオフにすると保存しませんが、
その録音は**あとから文字起こしできなくなります**（録音自体は通常どおり行われます）。

### 作業用音声の削除設定

設定画面の「**文字起こしが完了したら作業用音声を削除する**」で切り替えます。

| 状況 | 動作 |
| --- | --- |
| 設定オン・文字起こしが正常完了 | 作業用音声を削除します |
| 設定オフ・文字起こしが正常完了 | 作業用音声を残します |
| 文字起こしが**失敗** | **削除しません** |
| 文字起こしを**中止** | **削除しません** |

失敗・中止のときに削除しないのは、次にやることが「もう一度試す」だからです。
入力を消してしまうと、それができなくなります。

**削除すると、その録音は別のモデルで文字起こしし直せなくなります**
（録音した音声は残りますが、系統別の作業音声は復元できません）。
左パネルの「読み込まれている音声」欄に、いま再文字起こしできるかどうかを表示します。

インポートした音声の場合は、**元のファイルが同じ場所にある限り**、
作業音声を削除したあとでも自動的に作り直して再実行できます。

## 音声処理の方針

MeetingRecorder では、保存音声および Whisper 認識用音声について、
**音声認識への悪影響を避けるため過度な音声加工を行いません。**

Noise Gate、AGC（自動ゲイン制御）、Compressor、Limiter といった
**時間変動・非線形な処理は使用しません**。音量調整が必要な場合も、
**波形全体に対する一定の固定ゲインのみ**を使用します。
文字起こし用音声については、元音声の情報保持を優先します。

### 実際に行っている処理のすべて

| 対象 | 処理 |
| --- | --- |
| 認識用音声（`recognition-*.wav`） | DCオフセット除去 → 16kHz へのサンプルレート変換 → モノラル化 → 16bit PCM 化。**それだけです** |
| 保存音声（`meeting.wav` / `.mp3`） | DCオフセット除去 → 各系統に一定の -6.02 dB → 加算 → **録音終了後にファイル全体へ一定ゲインを1回** |

DC オフセット除去は 20 Hz の1次ハイパスです。成人男性の最も低い基本周波数
（およそ 80 Hz）の1オクターブ下にあり、音声帯域には実質的な影響を与えません。
残している理由は「元からあったから」ではなく、DC オフセットがヘッドルームを消費して
後段の固定ゲインを小さくしてしまい、ピーク測定も歪めるためです。

### 音量調整の式

```
peak = max |input[n]|                          （ファイル全体を走査）
gain = min( 10^(-1/20) / peak , 10^(20/20) )   （目標 -1 dBFS、上限 +20 dB）
output[n] = input[n] * gain                    （全サンプルに同じ gain）
```

`gain` は `n` に依存しません。したがってこの処理は**線形かつ時不変**であり、

- 話し始めの小さい音
- 子音
- 小声・大声
- 無音
- 発話のダイナミクス

の**相対関係は一切変化しません**。無音は無音のまま残ります。

### クリッピングの防ぎ方

**ゲインを先に決めることで防ぎます。** 閾値で切り落とす処理（ハードクリップ）や
リミッターは使いません。

- **録音中**: マイク系統と PC 音声系統に、それぞれ一定の **-6.02 dB（＝ちょうど 0.5 倍）**
  を掛けてから加算します。両方が同時にフルスケールでも、合計はちょうどフルスケールに
  収まります。この 6 dB は、録音終了後の固定ゲインで返します。
- **録音終了後**: ファイル全体の実際のピークを測ってからゲインを決めるため、
  ゲイン適用後のピークは目標値（-1 dBFS）**以下**にしかなりません。
  ちょうど -1 dBFS になるのは `gain = 10^(-1/20) / peak` が上限に当たらなかった場合で、
  音が小さすぎて上限 +20 dB に当たった場合は -1 dBFS より小さいまま終わります。
  なお、計算したゲインが 0 dB から ±0.1 dB 未満（ピークがすでに -1.1 〜 -0.9 dBFS）の
  ときは、書き直しても意味がないためファイルをそのまま残します。
  いずれの場合もフルスケールを超えるサンプルは発生しません。

目標を -1 dBFS にしている理由は、PCM のサンプルピークが、DA 変換や非可逆圧縮で
サンプル間に再構成される真のピーク（true peak）と一致しないためです。
ITU-R BS.1770-4 / EBU R 128 が同じ理由で -1 dBTP の余裕を推奨しており、同じ値を
同じ理由で採っています。16bit 量子化の丸めもここに吸収されます。

上限 +20 dB（10倍）を設けているのは、それ以上増幅しても持ち上がるのは
発話ではなく収録時のノイズフロアだからです。10倍より大きなゲインは、
会議を聞き取りやすくも文字起こししやすくもしません。

これらの定数はすべて `AudioProcessingSettings` の1箇所に集約され、
各値の根拠がコード内のコメントに記載されています。

### 元音声が既に歪んでいる場合

キャプチャ時点で既にクリッピングしている音声は、**後処理では復元できません。**
検出した場合は、ログ・警告・`metadata.json`（`sourceClipped`）に記録し、
ユーザーに入力レベルを下げるよう促します。**「修復できた」とは表示しません。**

### 注意

ここに書いたのは「何をしているか」と「なぜそうしているか」です。
**この方針によって文字起こし精度が必ず向上する、とは主張していません。**
検証しているのは、加工が実際に行われていないこと（`DspTests`）であり、
日本語の認識精度そのものは実機での評価が必要です。

## 録音データの自動保存と出力

既定では、録音は停止と同時に会議フォルダーへ保存されます。
設定でこれをオフにすると、**保存先を毎回自分で選ぶ**運用にできます。

- オフでも、**録音中は必ずディスクへ書き込みます**（作業用フォルダー）。
  メモリに溜める方式にすると、クラッシュや電源断で会議が丸ごと消えるためです。
- 「**音声を出力...**」ボタンで、直前の録音を任意の場所へコピーします。
  元のデータは残るので、出力に失敗しても失われません。
- 未出力の録音があるまま終了しようとすると、件数と場所をお知らせします
  （**自動では削除しません**）。

## 議事録の生成（実験的）

**文字起こしの結果がある場合のみ**、「議事録を生成（実験的）」を押したときに実行されます。
録音しただけの状態では実行できません（ボタンが無効になります）。議事録は文字起こしの本文から
作るものなので、本文がない状態で作れるものは何もないためです。

```
音声なし → 音声あり → 文字起こし中 → 文字起こし完了 → 議事録生成
```

出力形式:

```markdown
# 会議議事録
## 1. 概要
## 2. 決定事項
## 3. 議題別内容
## 4. ToDo・ネクストアクション
## 5. 継続検討事項
## 6. 補足
```

- 文字起こしに書かれていない情報は補完しません。
  担当者・期限が不明な場合は **`要確認`** と記載されます。
- ローカルLLMのモデルが未取得の場合は、
  文字起こしから**原文のまま**キーフレーズを抽出する方式で生成します。
- 生成AIの出力には誤りが含まれます。必ず `transcript.md` の原文で確認してください。

## 保存先とファイル構成

会議ごとに 1 フォルダーが作られます。

このアプリで録音した会議:

```
2026-09-07_1430_Meeting/
├── meeting.wav              （または meeting.mp3）
├── recognition-mic.wav      ← 文字起こし用の作業音声（マイク系統）
├── recognition-system.wav   ← 文字起こし用の作業音声（PC音声系統）
├── transcript.txt           ← 「文字起こし」を実行した場合
├── transcript.md            ← 同上
├── minutes.txt              ← 「議事録を生成」を実行した場合
├── minutes.md               ← 同上
└── metadata.json
```

インポートした音声:

```
2026-09-07_1512_interview/
├── recognition-import.wav   ← 元ファイルから作った作業音声（16kHz/モノラル）
├── transcript.txt / transcript.md
├── minutes.txt / minutes.md
└── metadata.json
```

インポートの場合、**音声の本体はユーザーが指定した元のファイル**であり、
会議フォルダーにはコピーされません（`metadata.json` にパスだけ記録します）。
`recognition-*.wav` は設定により文字起こし完了後に削除されます。
ファイル名は従来どおりで、後方互換です。

現在の保存先はメイン画面に常時表示され、「保存先を開く」で開けます。

**自動保存とクラッシュ復旧**

音声は逐次書き込まれ、認識結果は追記専用ジャーナルに逐次保存されます。
停止ボタンを押さずにアプリが落ちても（強制終了・電源断を含む）、
次回起動時に「前回の会議データを復旧しますか？」と表示され、
文字起こしと議事録ファイルを再生成できます。音声ファイルはそのまま再生できます。

## WAV と MP3

| 形式 | 設定 | 1時間あたり | 用途 |
| --- | --- | --- | --- |
| WAV | 48kHz / 16bit / モノラル | 約 346 MB | 無圧縮。元の波形をそのまま残したい場合 |
| MP3 | 128 kbps | 約 58 MB | さらに小さくしたい場合 |
| MP3 | **192 kbps** | 約 86 MB | **既定**。長期保存・共有 |
| MP3 | 256 kbps | 約 115 MB | |
| MP3 | 320 kbps | 約 144 MB | |

ビットレートは設定画面で選べます。

> **既定が MP3 である理由。** 1時間の会議が WAV なら約 346 MB、MP3 192 kbps なら
> 約 86 MB です。**気づかないうちにドライブが埋まる**のは、意識して選んだ設定では
> なく、誰も見なかった設定によって起きます。
> **文字起こしの精度はこの選択に影響されません。** Whisper が読むのは
> `recognition-*.wav`（16 kHz PCM・キャプチャからそのまま書き出したもの）であり、
> この会議ファイルではありません。会議ファイルは人が聴くためのものです。
> 元の波形をそのまま残したい場合は WAV を選んでください。

> **モノラルであることに注意してください。** 「192 kbps はステレオ音楽なら十分」
> という感覚でこの数字を見ると過小評価になります。ここでの 192 kbps は
> **1チャンネルに 192 kbps** を割り当てるという意味で、
> ステレオ 384 kbps に相当する割り当てです。会議の音声には十分すぎる余裕があります。
> 逆に、**劣化を一切許容しない用途では WAV（既定）を選んでください。**
> MP3 はどのビットレートでも非可逆です。

> **ビットレートは「要求」であって「指定」ではありません。** エンコーダーは
> 出力可能な形式を固定の一覧として持っており、そこに無い値を要求すると
> 最も近いものが使われます。実際に使われた値は `metadata.json` の
> `mp3BitrateKbps` に記録され、要求と異なった場合は画面にも表示します。

MP3 は Windows 標準の Media Foundation エンコーダーを使います
（追加インストール不要、LGPL ライブラリの同梱なし）。

録音は常に WAV で書き込まれ、停止後に MP3 へ変換されます。
これは、クラッシュ時に途中までのファイルが確実に再生できるようにするためです。
変換が成功した場合のみ WAV が削除されます。

**したがって MP3 を選んでも、録音中に必要な空き容量は減りません。**
減るのは「録音が終わったあとに残る量」です。

### 1時間の会議に必要な容量（既定設定）

| 局面 | 使用量 |
| --- | --- |
| 録音中（ピーク） | 約 576 MB（`meeting.wav` 346 MB ＋ 作業音声 2系統 230 MB） |
| 録音停止後 | 約 317 MB（`meeting.mp3` 86 MB ＋ 作業音声 230 MB） |
| **文字起こし後** | **約 86 MB**（作業音声は既定で削除されます） |

作業音声（`recognition-mic.wav` / `recognition-system.wav`）は**1系統あたり約 115 MB/時**
かかり、**文字起こしを実行しない限り残り続けます**。設定画面に現在の設定での
使用量が常に表示されます。

## 既知の制約

| 制約 | 内容 |
| --- | --- |
| 文字起こしの所要時間 | 録音に追いつく設計ではありません。モデルによっては、1時間の会議に1時間以上かかります。設定画面に推定値を表示します |
| 話者分離の精度 | MFCC + クラスタリングによる軽量実装です。ニューラル話者埋め込みではありません。**同時発話は分離できません。声質の似た2人は同一クラスタに統合され、マイクとの距離が変わった同一人物は別クラスタに分割されることがあります。** 実用上は「おおよその目安」であり、正確な話者特定には使えません。一方で「マイク / PC音声」の分類は録音ストリームで確定するため常に正確です |
| インポート音声の話者 | **判別しません。** 1本の音声には音源の情報がないため、推測はしません |
| `.aac`（生ADTS） | 環境依存で、CI では未検証です（上記の注記を参照） |
| MP3 / M4A / AAC のデコード | Windows の Media Foundation に依存します。N / KN エディションでは Media Feature Pack が必要です |
| PC音声の取得範囲 | 再生デバイスの出力**全体**です。特定アプリのみを録音することはできません（Windows の通知音なども入ります） |
| Bluetooth ヘッドセット | ハンズフリー(HFP)モードでは再生品質が大きく下がります。ステレオ(A2DP)での使用を推奨します |
| ループバック元の必要性 | PC内部音声は再生デバイスのループバックとして取得するため、再生デバイスが存在しない環境では取得できません |
| コード署名なし | SmartScreen の警告が出ます（上記参照） |
| 議事録生成の速度 | 基準PCで 1 時間の会議あたり数分〜十数分かかります |
| 作業音声を削除した録音 | 別のモデルでの再文字起こしはできません（インポート音声は元ファイルがあれば可能） |
| 過去の会議を開き直す機能 | ありません。アプリは「いま録音した／いま読み込んだ」会議だけを対象にします。過去のフォルダーを文字起こししたい場合は、その `meeting.wav` を**インポート**してください（この場合、マイク／PC音声の区別は失われ「インポート音声」になります） |
| クラッシュ復旧した会議の文字起こし | 復旧ダイアログは音声と文字起こしファイルを復元しますが、その場で文字起こしを実行することはできません。上と同じく `meeting.wav` のインポートで対応できます |
| 英語等の混在 | 認識言語は日本語固定です（設定で変更可能ですが、既定は `ja`） |
| 実機未検証項目 | CI では実オーディオデバイスを用いた検証ができません。`TEST_RESULTS.md` と `docs/WINDOWS_E2E_TEST.md` を参照してください |

## トラブルシューティング

**まず自己診断を実行してください**

コマンドプロンプトから次を実行すると、デバイス・権限・保存先・空き容量・
モデル・外部通信の状態をまとめて実測できます。

```
MeetingRecorder.exe --diagnose --seconds 10
```

実行中の10秒間、マイクに向かって話し、PCで何か音声を再生してください。
レポートは `<展開先>\data\logs\` にも保存されるので、そのまま情報システム部門に
渡すことができます。

**マイクのレベルメーターが動かない**
- Windows 設定 →「システム」→「サウンド」→「入力」でデバイスを確認
- 「プライバシーとセキュリティ」→「マイク」→
  「デスクトップ アプリがマイクにアクセスできるようにする」が**オン**か確認
- 設定画面で「デバイス一覧を再取得」を実行

**PC内部音声のレベルメーターが動かない**
- 何か音声を再生してください（WASAPI ループバックは無音時にデータを返しません）
- 設定画面で、実際に音が出ている再生デバイスが選ばれているか確認
- Bluetooth の場合、ハンズフリー側ではなくステレオ側を選択

**録音した音声が途切れる／聞き取りづらい**
- まず、録音停止後の警告と、画面下の診断表示にある「無音補間」を確認してください。
  ここが 0.0s 以外であれば、その秒数分だけマイクの音声が届かず、無音で埋められています。
  マイク系統でこれが録音全体の 0.1% を超えた場合は、停止時に警告が出ます。
- 録音中に重い処理（ビルド、動画書き出し、大量のファイルコピー等）を
  同時に動かしていた場合は、それを止めてから録音してください。
- レベルメーターが極端に小さい場合は、Windows 設定 →「サウンド」→「入力」で
  デバイスの音量を上げてください。**アプリ側で音量を持ち上げるのは
  録音終了後の一定ゲイン1回だけ**で、収録時に小さすぎた音声を
  後から復元することはできません。

**録音中に文字起こしが表示されない**
- 仕様です。録音中は文字起こしを行いません。
  録音を停止したあとに「文字起こし」を押してください。

**「文字起こし」ボタンが押せない**
- 録音済みまたはインポート済みの音声がない（まず録音するかインポートしてください）
- 設定で「文字起こし機能を使う」がオフになっている
- 録音時に「文字起こし用の音声を保存する」がオフだった
  （その録音は文字起こしできません。左パネルの「読み込まれている音声」に理由が出ます）
- 作業用音声を削除済みで、元ファイルもない

**文字起こしが失敗する**
- 設定画面でモデルが「取得済み」になっているか確認
- メモリ不足の場合は、他のアプリを閉じるか、設定画面で小さいモデルを選んでください
- 失敗しても録音データは消えません。ログ `data\logs\meetingrecorder.log` を確認してください

**文字起こしが遅い**
- 設定画面でモデルを選ぶと推定処理時間が表示されます。より小さいモデルを選べば短くなります
- 「PC性能を測定して自動設定」で、このPCに合った既定値を選び直せます

**MP3 で保存されない**
- 設定画面に「MP3エンコーダーが見つかりません」と出ていないか確認
  （Windows N/KN エディションでは Media Feature Pack が必要）

**録音中にヘッドセットを抜いてしまった**
- 自動再接続を試みます。復帰の可否はメイン画面に表示されます
- 復帰できなかった場合、そのストリームは無音として記録されます。
  録音自体は継続しているので、一度停止して保存してから録音し直してください

**アプリが落ちた**
- 再起動すると復旧ダイアログが表示されます
- 音声ファイルは落ちる直前まで再生できます

**設定やログはどこに保存されますか**
- 実行ファイルの隣に書き込めれば `<展開先>\data\`（ポータブルモード）
- 書き込めない場合は `%LOCALAPPDATA%\MeetingRecorder\`
- 設定画面の「保存場所」に実際のパスが表示されます

## 開発者向け

### ビルドとテスト

```powershell
dotnet restore MeetingRecorder.sln
dotnet build   MeetingRecorder.sln --configuration Release
dotnet test    MeetingRecorder.sln --configuration Release
```

Windows 向けの配布物は次で作れます（詳細は [`BUILD.md`](BUILD.md)）。

```powershell
dotnet publish src/MeetingRecorder.App/MeetingRecorder.App.csproj `
  --configuration Release --runtime win-x64 --self-contained true
```

WPF を含む完全なビルドには Windows が必要です。Linux / macOS では
`Core` / `Stt` / `Diarization` / `Minutes` / `Audio` とそのテストのみビルド・実行できます。
