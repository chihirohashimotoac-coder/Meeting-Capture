# MeetingRecorder

Windows 11 向けの **ポータブル会議録音・リアルタイム文字起こしアプリケーション**です。

ZIP を展開して `MeetingRecorder.exe` を起動し、「録音開始」を押すだけで、
**マイク（同じ部屋の参加者）と PC 内部音声（Zoom / Teams / Meet / ブラウザなど、
Windows が再生している音すべて）を同時に録音**し、日本語の文字起こしを
**完全にローカルで**行います。

インストール不要・管理者権限不要・会議データの外部送信なし。

## アプリ概要

| 機能 | 内容 |
| --- | --- |
| マイク録音 | WASAPI で任意の入力デバイスから取得 |
| PC内部音声録音 | **WASAPI ループバック**。再生デバイスの出力全体を取得（特定アプリ専用ではありません） |
| 音量補正 | ストリームごとに DC除去 → ソフトゲート → ラウドネス正規化 → コンプレッサー → リミッター |
| 保存 | 補正・ミックス済みの **1ファイル**（WAV または MP3） |
| 文字起こし | whisper.cpp による日本語認識。**完全ローカル・CPU実行** |
| 発言元 | 「マイク」「PC音声」を録音ストリームで確定（AI推測ではありません） |
| 話者分離 | PC音声側を `Speaker 1/2/...` に分類（実験的・精度は限定的） |
| 議事録 | 録音停止後に手動実行。ローカルLLM または 抽出型（実験的） |
| クラッシュ復旧 | 停止ボタンを押さずに落ちてもデータが残り、次回起動時に復旧 |
| 性能自動調整 | PC性能を**実測**してモデル・スレッド数・機能を自動選択 |

## 対応OS・必要PC性能

| 項目 | 要件 |
| --- | --- |
| OS | Windows 11（Windows 10 でも動作します） / x64 |
| 管理者権限 | **不要** |
| CPU | 4コア以上を推奨。基準環境: Intel Core i5-1335U |
| RAM | 8GB 以上（推奨 16GB） |
| GPU | **不要**。CPU のみで動作します（NVIDIA GPU は不要） |
| ディスク | アプリ約 300MB + モデル（60MB〜540MB）+ 録音データ（WAV 約338MB/時、MP3 約43MB/時） |
| 事前インストール | .NET / Python / Node.js / Visual C++ ランタイム いずれも**不要** |
| 仮想オーディオドライバ | **不要**（VB-CABLE、Stereo Mix 等に依存しません） |

## プライバシーと外部通信

このアプリは会議データを機密情報として扱います。

**自分で確認する方法**

```
MeetingRecorder.exe --diagnose          # アプリ自身が保持する外向き接続を表示
tools\Verify-NoNetwork.ps1 -Minutes 10  # プロセス外部から接続を監視
```

**送信しないもの（実装上、送信経路が存在しません）**

- マイク音声 / PC内部音声 / 録音データ
- 文字起こし / 議事録 / 発言者情報
- 利用状況・クラッシュログ・アクセス解析（テレメトリーは一切ありません）

**使用していないクラウドサービス**

OpenAI API、Anthropic API、Gemini API、Azure Speech、Google Speech、
AWS Transcribe、その他クラウド AI / STT API。

**唯一の外部通信: AIモデルの初回ダウンロード**

- ユーザーが明示的にボタンを押した場合のみ実行されます。
- 開始前に、モデル名・用途・配布元・URL・ファイルサイズ・保存先・
  ライセンス・SHA-256 を画面に表示します。
- URL は `ModelCatalog` にハードコードされた許可リストのみ。
  任意の URL を入力する機能はありません。HTTPS 以外は拒否します。
- ダウンロード後に **SHA-256 を照合**し、不一致ならファイルを削除して失敗させます。

**ログ**

技術ログ（エラー、デバイスイベント、バッファ状況、STT処理時間など）は
ローカルにのみ保存されます。会議本文や文字起こし全文はログに複製しません。

## 入手と起動方法

1. GitHub Actions の最新の成功したビルドを開きます
   （[Actions タブ](../../actions/workflows/build-windows.yml)）。
2. Artifacts から `MeetingRecorder-win-x64` をダウンロードします。
3. 中の `MeetingRecorder-win-x64.zip` を、書き込み可能な任意のフォルダーに展開します。
   （例: `C:\Users\<ユーザー名>\Tools\MeetingRecorder\`。Program Files 配下は避けてください）
4. `MeetingRecorder.exe` をダブルクリックします。

タグ `v*` を push した場合は、GitHub Release（**下書き**として作成されます）からも取得できます。

### 最初に 1 回だけ実行することを推奨します

展開したフォルダーでコマンドプロンプトを開き、次を実行してください。
マイク・PC内部音声・保存先・空き容量・外部通信の状態を **実測** して表示します。

```
MeetingRecorder.exe --diagnose --seconds 10
```

実行中の 10 秒間、マイクに向かって話し、PC で何か音声（動画やテスト音）を再生してください。
ここで `D-04`（マイク）と `D-05`（PC内部音声）が **[ OK ]** になれば、その PC で
本アプリの中核機能が動くことが確認できたことになります。逆にここでエラーが出た場合は、
録音を始める前に表示された対処を行ってください。

## SmartScreen について

実行ファイルにコード署名をしていないため、初回起動時に
**「Windows によって PC が保護されました」**と表示されることがあります。

- 「詳細情報」→「実行」で起動できます。
- ZIP のプロパティに「セキュリティ: このファイルは他のコンピューターから
  取得したものです」が表示される場合は、「許可する」にチェックしてから展開すると
  警告が出にくくなります。
- 組織のポリシーで実行がブロックされる場合は、情報システム部門にご相談ください。

## 初回設定

初回起動時にウィザードが表示されます。

1. **マイク** — 入力デバイスを選択（既定デバイスに追従させることもできます）
2. **PC音声** — ループバック取得元の再生デバイスを選択
3. **保存先** — 録音データを保存するフォルダーを選択
4. **AIモデル** — 「PC性能を測定」→「モデルをダウンロード」

設定はローカルに保存され、2 回目以降は
**`MeetingRecorder.exe` を起動 → 「録音開始」** だけで使えます。

> モデルを取得しなくても **録音は利用できます**。その場合、文字起こしのみ行われません。

## AIモデルの取得

| モデル | サイズ | ライセンス | 用途 |
| --- | --- | --- | --- |
| Whisper tiny (q5_1) | 約31MB | MIT | 最軽量 |
| Whisper base (q5_1) | 約57MB | MIT | 軽量 |
| Whisper small (q5_1) | 約181MB | MIT | **推奨**（基準PCでの実用点） |
| Whisper medium (q5_0) | 約514MB | MIT | 高精度・高負荷 |
| Qwen2.5 1.5B Instruct (GGUF) | 約1.04GB | Apache-2.0 | 議事録生成（既定） |
| Qwen2.5 3B Instruct (GGUF) | 約1.96GB | Qwen Research License | 議事録生成（**自動選択されません**。社内利用可否の確認が必要） |

どのモデルを使うかは、PC性能の**実測結果**から自動的に決まります。
「高速／標準／高精度」をユーザーが選ぶ必要はありません。

## 録音する

1. （任意）会議名を入力します。フォルダー名に使われます。
2. 録音開始前に、左パネルの **マイク／PC内部音声のレベルメーター**が
   振れていることを確認してください。片方が無音のまま 1 時間録音してしまう事故を防げます。
3. 「● 録音開始」を押します。

録音開始時に以下が自動チェックされ、問題があれば
**原因と対処方法**が表示されます（"Error" だけの表示はしません）。

- マイクが取得できるか
- PC内部音声が取得できるか
- 保存先に書き込めるか
- 十分な空き容量があるか
- STTモデルが利用可能か

録音中は、録音時間・レベルメーター・文字起こし・処理遅延・
診断情報（CPU / RAM / RTF / バックログ / バッファ溢れ / 同期補正）が表示されます。

録音中は Windows のスリープが抑制され、停止すると元に戻ります。

## 文字起こし

録音開始と同時にリアルタイムで開始されます。表示例:

```
[00:01:24] マイク
今回のKPIについて確認します。

[00:01:31] PC音声 / Speaker 1
はい。前月実績についてですが……
```

- **本文はその場で編集できます**（誤変換の修正、削除、追記）。
- 「話者名を編集」で `Speaker 1 → 大西` のように変更でき、
  その会議内の同じ話者の発言すべてに一括反映されます。
- アプリが人物名を推測することはありません。実名はユーザーが入力した場合のみ表示されます。

文字起こしが録音に追いつかない場合は
「文字起こし処理遅延: 18秒」のように表示されます。
**遅れても音声データが捨てられることはありません**（キューがディスクへ退避されます）。

## 議事録の生成（実験的）

録音停止後に「議事録を生成（実験的）」を押した場合のみ実行されます（リアルタイム生成はしません）。

出力形式:

```markdown
# 会議議事録
## 1. 概要
## 2. 決定事項
## 3. 議題別内容
## 4. ToDo・ネクストアクション
## 5. 継続検討事項
## 6. 補足
```

- 文字起こしに書かれていない情報は補完しません。
  担当者・期限が不明な場合は **`要確認`** と記載されます。
- ローカルLLMのモデルが未取得の場合は、
  文字起こしから**原文のまま**キーフレーズを抽出する方式で生成します。
- 生成AIの出力には誤りが含まれます。必ず `transcript.md` の原文で確認してください。

## 保存先とファイル構成

会議ごとに 1 フォルダーが作られます。

```
2026-09-07_1430_Meeting/
├── meeting.wav        （または meeting.mp3）
├── transcript.txt
├── transcript.md
├── minutes.txt        ← 議事録を生成した場合
├── minutes.md         ← 議事録を生成した場合
└── metadata.json
```

現在の保存先はメイン画面に常時表示され、「保存先を開く」で開けます。

**自動保存とクラッシュ復旧**

音声は逐次書き込まれ、認識結果は追記専用ジャーナルに逐次保存されます。
停止ボタンを押さずにアプリが落ちても（強制終了・電源断を含む）、
次回起動時に「前回の会議データを復旧しますか？」と表示され、
文字起こしと議事録ファイルを再生成できます。音声ファイルはそのまま再生できます。

## WAV と MP3

| 形式 | 設定 | 1時間あたり | 用途 |
| --- | --- | --- | --- |
| WAV | 48kHz / 16bit / モノラル | 約 338 MB | 既定。再編集・再解析する場合 |
| MP3 | 96 kbps | 約 43 MB | 長期保存・共有 |

MP3 は Windows 標準の Media Foundation エンコーダーを使います
（追加インストール不要、LGPL ライブラリの同梱なし）。

録音は常に WAV で書き込まれ、停止後に MP3 へ変換されます。
これは、クラッシュ時に途中までのファイルが確実に再生できるようにするためです。
変換が成功した場合のみ WAV が削除されます。

## 既知の制約

| 制約 | 内容 |
| --- | --- |
| 話者分離の精度 | MFCC + クラスタリングによる軽量実装です。同時発話は分離できません。声質の似た話者は統合され、マイクとの距離が変わると同一人物が分割されることがあります。「マイク / PC音声」の分類は常に正確です |
| PC音声の取得範囲 | 再生デバイスの出力**全体**です。特定アプリのみを録音することはできません（Windows の通知音なども入ります） |
| Bluetooth ヘッドセット | ハンズフリー(HFP)モードでは再生品質が大きく下がります。ステレオ(A2DP)での使用を推奨します |
| ループバック元の必要性 | PC内部音声は再生デバイスのループバックとして取得するため、再生デバイスが存在しない環境では取得できません |
| コード署名なし | SmartScreen の警告が出ます（上記参照） |
| 議事録生成の速度 | 基準PCで 1 時間の会議あたり数分〜十数分かかります |
| 英語等の混在 | 認識言語は日本語固定です（設定で変更可能ですが、既定は `ja`） |
| 実機未検証項目 | CI では実オーディオデバイスを用いた検証ができません。`TEST_RESULTS.md` と `docs/WINDOWS_E2E_TEST.md` を参照してください |

## トラブルシューティング

**まず自己診断を実行してください**

コマンドプロンプトから次を実行すると、デバイス・権限・保存先・空き容量・
モデル・外部通信の状態をまとめて実測できます。

```
MeetingRecorder.exe --diagnose --seconds 10
```

実行中の10秒間、マイクに向かって話し、PCで何か音声を再生してください。
レポートは `<展開先>\data\logs\` にも保存されるので、そのまま情報システム部門に
渡すことができます。

**マイクのレベルメーターが動かない**
- Windows 設定 →「システム」→「サウンド」→「入力」でデバイスを確認
- 「プライバシーとセキュリティ」→「マイク」→
  「デスクトップ アプリがマイクにアクセスできるようにする」が**オン**か確認
- 設定画面で「デバイス一覧を再取得」を実行

**PC内部音声のレベルメーターが動かない**
- 何か音声を再生してください（WASAPI ループバックは無音時にデータを返しません）
- 設定画面で、実際に音が出ている再生デバイスが選ばれているか確認
- Bluetooth の場合、ハンズフリー側ではなくステレオ側を選択

**文字起こしが表示されない**
- 設定画面でモデルが「取得済み」になっているか確認
- メイン画面下部の「文字起こし処理遅延」を確認（大きく遅れているだけかもしれません）
- ログ `data\logs\meetingrecorder.log` を確認

**文字起こしが遅い / CPU使用率が高い**
- 設定画面で「PC性能を測定して自動設定」を実行してください
- 実測 RTF が高い場合、話者分離 → 軽量モデル の順に自動的に機能が落とされます

**MP3 で保存されない**
- 設定画面に「MP3エンコーダーが見つかりません」と出ていないか確認
  （Windows N/KN エディションでは Media Feature Pack が必要）

**録音中にヘッドセットを抜いてしまった**
- 自動再接続を試みます。復帰の可否はメイン画面に表示されます
- 復帰できなかった場合、そのストリームは無音として記録されます。
  録音自体は継続しているので、一度停止して保存してから録音し直してください

**アプリが落ちた**
- 再起動すると復旧ダイアログが表示されます
- 音声ファイルは落ちる直前まで再生できます

**設定やログはどこに保存されますか**
- 実行ファイルの隣に書き込めれば `<展開先>\data\`（ポータブルモード）
- 書き込めない場合は `%LOCALAPPDATA%\MeetingRecorder\`
- 設定画面の「保存場所」に実際のパスが表示されます
