# Windows 実機テスト手順

**このドキュメントの目的**

GitHub Actions の Windows ランナーには、実マイク・実スピーカー・実オーディオセッション・
会議アプリケーションが存在しません。したがって **CI のビルド成功とテスト成功は、
WASAPI の実機動作を確認したことにはなりません。**

以下の項目は、実際の Windows 11 PC で人間が実行して初めて「確認済み」となります。
結果は `TEST_RESULTS.md` の「Windows physical machine」欄に記録してください。

---

## 0. 準備

| 項目 | 内容 |
| --- | --- |
| 対象PC | Windows 11 x64（基準: Core i5-1335U / RAM 16GB / 内蔵GPU / 管理者権限なし） |
| 配布物 | GitHub Actions の Artifact `MeetingRecorder-win-x64` から `MeetingRecorder-win-x64.zip` を取得 |
| 展開先 | 例: `C:\Users\<user>\Tools\MeetingRecorder\`（Program Files 以外の書き込み可能な場所） |
| 事前条件 | .NET / Python / Node.js / VC++ ランタイムを **インストールしないこと**（自己完結性の確認のため） |
| 記録 | 各項目の結果、Windows のバージョン（`winver`）、実行日時、使用デバイス名 |

ログの場所（トラブル時に添付）:
`<展開先>\data\logs\meetingrecorder.log`
（展開先が書き込み不可の場合は `%LOCALAPPDATA%\MeetingRecorder\logs\`）

## 0.5 まず `--diagnose` を実行する（推奨）

多くの項目は、アプリの自己診断モードで一度に確認できます。
**コマンドプロンプトまたは PowerShell** から実行してください。

```
cd <展開先>
MeetingRecorder.exe --diagnose --seconds 10
```

実行中の10秒間に **マイクに向かって話し、同時にPCで何か音声を再生**してください。
（YouTube やテスト用の音源で構いません）

出力例:

```
[ OK ] D-01  録音デバイス (マイク)
       2 件: マイク配列 (Realtek(R) Audio)（既定） / ヘッドセット
[ OK ] D-05  PC内部音声取得テスト (WASAPIループバック)
       デバイス「スピーカー (Realtek(R) Audio)」から 10 秒間に 480,000 サンプル受信
       （想定の 100%）/ peak -6.2 dBFS / RMS -24.1 dBFS — 信号を検出しました。
[ OK ] D-08  外部通信
       このプロセスが確立している外向きTCP接続は 0 件です。
```

レポートは `<展開先>\data\logs\diagnose-YYYYMMDD-HHMMSS.txt` にも保存されます。

**この1コマンドでカバーされる項目**

| 診断ID | 対応する手順 | 内容 |
| --- | --- | --- |
| D-01 | T-04 | マイク認識 |
| D-02 | T-05 | 再生デバイス認識 |
| D-03 | T-06, T-43 | 録音開始前チェック（権限・保存先・空き容量） |
| D-04 | T-07 | マイクからの受信サンプル数とレベル |
| D-05 | **T-09** | **WASAPIループバックからの受信サンプル数とレベル** |
| D-06 | T-20 の一部 | CPU実測とモデル自動選択 |
| D-07 | T-22 の一部 | モデルの有無と SHA-256 照合記録 |
| D-08 | **T-45 の簡易版** | このプロセスの外向きTCP接続 |

**カバーされない項目**（以下は引き続き手動）: T-01/02/03（配布形態・SmartScreen）、
T-10〜12（Zoom/Meet/Teams の実音声）、T-13〜19（同時録音・同期・長時間）、
T-23〜36（文字起こし品質・保存形式）、T-37〜42（デバイス切断・スリープ・復旧）、
T-45b〜45e（音声ファイルのインポート）、T-46/47（議事録）。

### 外部通信の確認（T-45）

`--diagnose` の D-08 はアプリが自分自身の接続を報告するものです。
**プロセスの外側から**確認するには、同梱のスクリプトを使います。

```powershell
powershell -ExecutionPolicy Bypass -File tools\Verify-NoNetwork.ps1 -Minutes 10
```

実行中に「録音開始 → 数分待つ → 停止 → 議事録を生成」を行ってください。
外向き接続が 0 件であれば終了コード 0 になります。

より厳密な確認が必要な場合は Wireshark 等でのパケットキャプチャを併用してください。

## 1. 起動と配布形態

### T-01 ZIP 展開のみで起動できること
1. ZIP を右クリック →「すべて展開」。
2. `MeetingRecorder.exe` をダブルクリック。
3. **確認**: インストーラーが起動しないこと。UAC（管理者権限）の昇格ダイアログが出ないこと。
4. **確認**: .NET のインストールを促すダイアログが出ないこと。

**合格条件**: 追加インストールなしでウィンドウが表示される。

### T-02 SmartScreen の挙動
1. インターネットからダウンロードした ZIP（Mark-of-the-Web 付き）で T-01 を実行。
2. **記録**: 「Windows によって PC が保護されました」が出るか、
   「詳細情報」→「実行」で起動できるか、組織のポリシーでブロックされるか。

**合格条件なし（記録項目）**。署名していないため警告は想定内です。

### T-03 一般ユーザー権限での動作
1. 管理者権限を持たないアカウントでログオンし T-01 を実行。
2. 録音・モデルダウンロード・保存まで一通り実行。

**合格条件**: すべて昇格なしで完了する。

## 2. デバイス認識

### T-04 マイク認識
1. 初回設定ウィザードの「1. マイク」でドロップダウンを開く。
2. **確認**: 接続済みのマイク（内蔵マイク配列、USBヘッドセット等）が列挙される。
3. **確認**: 既定デバイスに「（既定）」が付く。

**合格条件**: 実際に接続しているデバイスがすべて表示される。

### T-05 再生デバイス認識（ループバック元）
1. ウィザードの「2. PC内部音声」でドロップダウンを開く。
2. **確認**: スピーカー／ヘッドセット／HDMI 出力等が列挙される。

**合格条件**: 実際の再生デバイスが表示される。

### T-06 マイクのプライバシー設定
1. Windows 設定 →「プライバシーとセキュリティ」→「マイク」で
   「デスクトップ アプリがマイクにアクセスできるようにする」を **オフ**にする。
2. 録音開始を押す。
3. **確認**: 「録音開始前チェック」でマイクがエラーになり、
   設定場所を含む具体的な対処方法が表示される（"Error" だけの表示は不合格）。
4. 設定を戻して再試行し、正常に開始できることを確認。

## 3. 音声レベルメーター（録音前）

### T-07 録音前にマイクレベルが振れること
1. アプリを起動し、**録音を開始せずに**マイクに向かって話す。
2. **確認**: 左パネルの「マイク」メーターが振れ、dBFS 値が更新される。

**合格条件**: 発話に追従してメーターが動く。

### T-08 録音前にPC音声レベルが振れること
1. 録音を開始せずに、YouTube などで音声を再生する。
2. **確認**: 「PC内部音声」メーターが振れる。
3. 再生を止めると数秒でメーターが下がる（無音時に WASAPI がデータを返さないため減衰表示）。

**合格条件**: 再生音に追従してメーターが動く。
これにより「録音したら片方が無音だった」を事前に検出できます。

## 4. WASAPI ループバック（中核機能）

### T-09 PC内部音声の取得（基本）

> 事前に `MeetingRecorder.exe --diagnose --seconds 10` の **D-05** で
> ループバックからサンプルが届いていることを確認しておくと切り分けが楽になります。

1. 録音開始。
2. YouTube 等で 30 秒程度、音声を再生。
3. 録音停止 → `meeting.wav` を再生。

**合格条件**: 再生した音声が録音されている。

### T-10 Zoom 音声の取得
1. Zoom ミーティングに参加（別端末から発話してもらう、または録音済み音声を流す）。
2. 録音開始 → 相手の発話を 1 分程度 → 停止。
3. `meeting.wav` と `transcript.txt` を確認。

**合格条件**: 相手の音声が録音され、文字起こしで `[PC音声]` として記録されている。

### T-11 Google Meet 音声の取得
T-10 と同手順を Google Meet（ブラウザ）で実施。

**合格条件**: 同上。

### T-12 Microsoft Teams 音声の取得
T-10 と同手順を Teams デスクトップアプリで実施。

**合格条件**: 同上。

### T-13 仮想オーディオドライバ非依存の確認
1. 対象PCに VB-CABLE / Virtual Audio Cable / Voicemeeter 等が
   **インストールされていない**ことを確認（`mmsys.cpl` の再生タブ）。
2. T-09 を実行。

**合格条件**: 追加ドライバなしで PC 内部音声が録音できる。

### T-14 Stereo Mix 非依存の確認
1. `mmsys.cpl` の録音タブで「ステレオ ミキサー」が無効または非搭載であることを確認。
2. T-09 を実行。

**合格条件**: ステレオミキサーなしで録音できる。

## 5. 同時録音と同期

### T-15 マイク + PC音声の同時録音
1. Zoom などで通話しながら、同じ部屋でも発話する。
2. 3 分程度録音して停止。
3. `meeting.wav` を再生。

**合格条件**: 室内の声と相手の声の **両方** が 1 ファイルに入っている。

### T-16 音声同期（30分）
1. 30 分録音（マイク・PC音声の双方に定期的に音を入れる。
   例: 10 分ごとに手拍子しながら PC でビープ音を鳴らす）。
2. 録音後、波形編集ソフト（Audacity 等）で開き、
   冒頭と末尾の同期用マーカーの間隔を比較。

**合格条件**: 冒頭と末尾で、マイク側と PC 音声側のマーカーのずれの差が **±100 ms 以内**。

### T-17 音声同期（1時間）
T-16 を 1 時間で実施。

**合格条件**: ずれの差が **±200 ms 以内**。
アプリ内「診断情報」の「同期補正」値も記録すること。

## 6. 長時間録音

### T-18 30分録音
1. 30 分間連続録音。
2. 診断情報（CPU / RAM / RTF / バックログ / バッファ溢れ）を 5 分ごとに記録。

**合格条件**:
- 録音が中断しない
- 「バッファ溢れ」が 0
- `meeting.wav` の長さが実時間 ±2 秒以内

### T-19 1時間録音
T-18 を 1 時間で実施。

**合格条件**: 同上（長さは実時間 ±5 秒以内）。
RAM 使用量が単調増加し続けていないことも確認（リーク検出）。

### T-20 CPU使用率
T-19 の間、タスクマネージャーで `MeetingRecorder.exe` の CPU 使用率を記録。

**目安**: 基準PC（i5-1335U）で、文字起こし有効時に平均 30% 以下。
超える場合は自動的に軽量モデルへ切り替わることを診断情報で確認。

### T-21 RAM使用量
T-19 の間、ワーキングセットを記録。

**目安**: Whisper small 使用時で 1.5 GB 以下。

## 7. 文字起こし

### T-22 モデルのダウンロード
1. 設定画面 →「モデルをダウンロード」。
2. **確認**: ダウンロード前に、モデル名・用途・配布元・URL・サイズ・保存先・
   ライセンス・SHA-256 が表示される。
3. ダウンロード実行。
4. **確認**: 進捗が実際のバイト数で進み、完了後に
   「SHA-256 照合に成功しました」と表示される。

**合格条件**: 照合成功。失敗する場合はファイルが削除され、エラーが表示されること。

### T-23 文字起こし（日本語・録音後）
1. モデル取得後に録音開始。
2. 日本語で 2〜3 分会話し、**録音を停止**する。
3. **確認**: 停止しただけでは文字起こしが始まらないこと。
   画面は「待機中（音声あり）」で止まり、進捗バーは出ない。
4. 「**文字起こし**」を押す。

**合格条件**:
- 押すまで文字起こしが 1 文字も現れない（押す前に現れたら不合格）
- 押したあと進捗が表示され、完了後に本文が現れる
- タイムスタンプ・発言元（マイク / PC音声）が表示される
- 明らかに発話していない箇所に定型文（「ご視聴ありがとうございました」等）が出ない

**記録項目**: 録音長、文字起こしに要した時間、使用したモデル。
（1時間の会議に対する実処理時間は、この手順でしか分かりません）

### T-23b 録音中に文字起こしが動かないこと
1. 録音を開始し、5 分ほど会話する。
2. タスクマネージャーで MeetingRecorder.exe の CPU 使用率とメモリを観察する。

**合格条件**:
- 文字起こし欄が空のまま
- CPU 使用率が数パーセント程度にとどまる（推論が走っていれば数十パーセントになります）
- メモリがモデルサイズ分（数百MB）増えない

**記録項目**: 録音中の CPU 使用率とワーキングセット。

### T-24 別のモデルでの再文字起こし
1. T-23 の会議に対して、設定画面でモデルを変更する。
2. もう一度「文字起こし」を押す。

**合格条件**: 結果がまるごと置き換わる。録音データは変化しない。

**前提**: 設定の「文字起こしが完了したら作業用音声を削除する」がオフであること。
オンのまま 1 回目を完了させた場合、この操作はできません（画面にその理由が表示されます）。

### T-25 小さい声・相槌の保持
1. 「はい」「うん」「なるほど」など短い相槌を挟んで録音。

**合格条件**: 相槌が文字起こしに現れる（すべてではなくとも、体感で大半が残る）。

### T-26 発言元の分離
1. マイクと PC 音声の双方で発話がある録音を実施。

**合格条件**: `transcript.txt` で `[マイク]` と `[PC音声]` が正しく分かれている。
（この分類はストリーム由来なので 100% 正しいはず。誤りがあれば不具合）

### T-27 話者分離（実験的）
1. PC 音声側に 2 名以上の話者がいる会議を録音。

**記録項目**: `PC音声 / Speaker 1`, `Speaker 2` に分かれるか。
**注意**: 精度は限定的です。分離できないこと自体は不合格ではありません。
録音や文字起こしが不安定になった場合のみ不合格。

### T-28 話者名の編集
1. 「話者名を編集」で `Speaker 1` に名前を入力して反映。

**合格条件**: 同一話者の発言すべてに一括反映され、`transcript.md` に保存される。

### T-29 文字起こしの編集
1. 画面上で本文を直接修正する。
2. 「文字起こしを保存」。

**合格条件**: `transcript.txt` / `transcript.md` に反映される。

## 8. 音量補正

> **前提の変更。** このアプリは音量差を「補正」しません。
> ゲート・AGC・コンプレッサー・リミッターはいずれも使わず、
> 録音終了後にファイル全体へ一定倍率のゲインを 1 回掛けるだけです。
> したがってここで確認するのは「揃っているか」ではなく
> **「余計なことをしていないか」**です。

### T-30 録音した音声が聞き取れる音量になっていること
1. 通常どおり会議を録音し、停止する。
2. `meeting.wav`（または `.mp3`）を再生する。

**合格条件**: 音量を上げなくても内容が聞き取れる。
**不合格の例**: ほとんど無音に聞こえる、あるいは歪んでいる。

**記録項目**: `metadata.json` の `appliedGainDb`（適用された固定ゲイン）。

### T-31 クリッピングが発生しないこと
1. 意図的に大音量（マイクに近接して大声、PC 音量最大）で録音。
2. Audacity 等で波形を確認。

**合格条件**:
- 波形が ±1.0 に張り付いていない（-1 dBFS 以下に収まる）
- 波形の頂点が**平ら**になっていない（平らならクリップしています）

**注意**: マイクの入力レベル自体が過大で、キャプチャ時点で既に歪んでいる場合、
アプリは警告を表示し `metadata.json` に `sourceClipped: true` を記録します。
**その歪みは後処理では直りません。** 警告が出た場合は入力レベルを下げて録り直してください。

### T-32 音量が時間とともに変化しないこと
1. 空調音のある部屋で、発話と沈黙を繰り返して 5 分録音し、停止する。
2. `meeting.wav` を Audacity 等で開く。

**合格条件**:
- 沈黙時に背景ノイズが**持ち上がらない**（AGC が無いことの確認）
- 発話開始時に音量が**急に変わらない**（ゲート／コンプレッサーが無いことの確認）
- 話し始めの小さな音や子音が**消えていない**

### T-32b 大小の声の比が保たれていること
1. 同じ録音の中で、小さめの声の区間と大きめの声の区間を選ぶ。
2. Audacity 等でそれぞれの RMS を測る。

**合格条件**: 両者の比が、耳で聞いた印象と一致する。
（コンプレッサーが掛かっていれば、この差は不自然に縮まります）

## 9. 保存形式

### T-33 WAV 保存
1. 設定で WAV を選択して録音。

**合格条件**: `meeting.wav` が生成され、標準の Windows Media Player 等で再生できる。
サイズが約 346 MB/時 であること。

### T-34 MP3 保存
1. 設定で MP3 を選択して録音・停止。

**合格条件**: `meeting.mp3` が生成され、再生できる。既定の 192 kbps なら約 86 MB/時。
`metadata.json` の `mp3BitrateKbps` が、設定で選んだ値と一致すること
（一致しない場合は、その旨の警告が画面に出ていること）。
`meeting.wav` は残っていない（変換成功時のみ削除される）。

### T-35 MP3 エンコーダー非搭載時の挙動
（Windows N/KN エディションがある場合のみ）
1. 設定画面を開く。

**合格条件**: 「MP3エンコーダーが見つかりません」と表示され、
MP3 を選んでも WAV で保存され、警告が出る。

### T-36 txt / md 保存
**合格条件**: `transcript.txt` と `transcript.md` が生成され、
会議日時・開始時間・timestamp・発言元・speaker・本文が含まれる。

## 10. 堅牢性

### T-37 音声デバイスの切断（USB）
1. USB ヘッドセットで録音開始。
2. 録音中に USB を **抜く**。
3. 30 秒待ってから挿し直す。

**合格条件**:
- アプリが落ちない
- 警告が表示される（自動復帰した場合はその旨、できなかった場合はその旨）
- 録音が継続し、停止後にファイルが再生できる

### T-38 音声デバイスの切断（Bluetooth）
T-37 を Bluetooth ヘッドセットで実施（電源を切る）。

**合格条件**: 同上。

### T-39 既定デバイスの変更
1. 録音中に Windows の既定の再生デバイスを切り替える。

**合格条件**: アプリが落ちない。警告が表示される。録音が継続する。

### T-40 スリープ抑制
1. 電源設定でスリープを「5 分」にする。
2. 録音を開始し、10 分間 PC を操作しない。

**合格条件**: 録音が継続している（スリープしない）。
録音停止後、10 分放置すると通常どおりスリープする（元の状態に戻る）。

### T-41 クラッシュ復旧
1. 録音を開始し、5 分程度録音する。
2. タスクマネージャーで `MeetingRecorder.exe` を **タスクの終了**（強制終了）。
3. アプリを再起動する。

**合格条件**:
- 起動時に「前回の会議データの復旧」ダイアログが表示される
- 「すべて復旧する」で `transcript.txt` / `transcript.md` が生成される
- `meeting.wav` が **強制終了直前まで**再生できる（修復ツール不要）

### T-42 電源断からの復旧
（可能な場合のみ）T-41 を、録音中に PC の電源ボタン長押しで実施。

**合格条件**: 同上。

### T-43 ディスク空き容量不足
1. 保存先を空き容量の少ないドライブ（USB メモリ等）に設定。
2. 録音開始を押す。

**合格条件**: 録音開始前チェックで警告またはエラーが表示され、
必要容量（WAV 約346MB/時）が案内される。

## 11. ネットワーク

### T-44 オフライン動作
1. PC をネットワークから切断する（機内モード / LAN 抜線）。
2. モデル取得済みの状態で、録音 → 停止 → 文字起こし → 保存 → 議事録生成、
   および音声ファイルのインポートを実行。

**合格条件**: すべて正常に動作する。

### T-45 通信の監視

> 簡易確認は `tools\Verify-NoNetwork.ps1 -Minutes 10` で実行できます。
> 以下は、より厳密に確認する場合の手順です。

1. Windows リソースモニターまたは Fiddler / Wireshark で
   `MeetingRecorder.exe` のネットワーク通信を監視。
2. 起動 → 録音 → 停止 → 文字起こし → 議事録生成 を実施。

**合格条件**: モデルダウンロード以外の外部通信が **一切発生しない**。
（この項目は本製品の中核的な要件です）

## 11.5 音声ファイルのインポート

### T-45b WAV のインポート
1. 手元の `.wav` を「音声ファイルをインポート...」から読み込む。
2. 「文字起こし」を押す。

**合格条件**:
- 読み込みに成功し、会議フォルダーが作られる
- **元のファイルが移動・変更・削除されていない**（更新日時とサイズを確認）
- 文字起こしの発言元がすべて「インポート音声」になっている
- 「話者名を編集」が押せない、または理由が表示される

### T-45c MP3 / M4A / AAC のインポート
1. `.mp3` / `.m4a` / `.aac` それぞれで T-45b を繰り返す。

**合格条件**: 読み込めるか、**理由を表示して断るか**のいずれか。
無言で失敗したり、壊れた結果を作ったりしないこと。

**記録項目**: どの形式が読めたか。特に `.aac`（生 ADTS）は
**CI で検証できていない**ため、実機の結果が唯一の情報です。

### T-45d インポート音声の再文字起こし
1. T-45b の会議で、作業用音声（`recognition-import.wav`）を手で削除する。
2. もう一度「文字起こし」を押す。

**合格条件**: 元のファイルから作業用音声が作り直され、文字起こしが実行される。
元のファイルを別の場所へ移動してから試すと、その旨が表示されること。

## 12. 議事録生成（実験的）

### T-45e 議事録は文字起こしの後でのみ実行できること
1. 録音を停止した直後（文字起こし未実行）に「議事録を生成」を押そうとする。

**合格条件**: ボタンが押せない、または理由が表示される。

### T-46 抽出型議事録
1. 議事録用モデルを取得していない状態で「議事録を生成」。

**合格条件**: `minutes.md` が生成され、6 セクション
（概要 / 決定事項 / 議題別内容 / ToDo / 継続検討事項 / 補足）が存在する。
不明な担当者・期限が `要確認` になっている。

### T-47 ローカルLLM議事録
1. 議事録用モデル（Qwen2.5 1.5B）を取得後に「議事録を生成」。

**合格条件**: 生成が完了する（基準PCで 1 時間会議あたり数分〜十数分）。
文字起こしに存在しない固有名詞・数値が捏造されていないこと（目視確認）。
生成中も録音済みデータが破損しないこと。
